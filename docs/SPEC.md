# Tokyo Ghoul Tracker — 仕様書 (v0.1)

更新日: 2026-10-12 / 状態: MVP実装基準 / 対象: スマスロ L東京喰種

## 1. 目的
ホール実戦中、iPhoneでCZ当選までの通常ゲーム数、CZ結果、AT終了時の獲得枚数を最少入力で記録し、ChatGPTへコピーできる時系列ログにする。**アプリ単体で設定を断定しない。**

## 2. 対象と非対象
- 対象: 1端末・1実戦のイベント記録、編集/削除、端末内自動保存、集計、AI入力文コピー、JSONバックアップ/復元。
- 非対象: 自動スクレイピング、外部API、設定別期待度計算、投資推奨、アカウント同期、AT獲得枚数からの設定判別。
- GitHub Pages上でバックエンド無しに動作する。初版はサーバーへデータを送らない。

## 3. 入力定義
- 実戦メタ: 日付(既定:当日)、店舗名(任意)、台番号(任意)。
- CZイベント: `通常G`(必須の0以上整数)、`CZ結果`(未確定/成功/失敗)。
- **通常G** は「着席または直前のCZ・AT終了などの記録起点から、当該CZに当選するまで、記録対象にした通常時の消化G」。CZ中・AT中のゲーム数は含めない。
- 記録漏れ・途中着席により網羅性が欠ける場合、通常G合計は **記録した区間合計** であり、必ずしも台の総ゲーム数に一致しない。
- ATイベント: `AT獲得枚数`(必須の0以上整数)。画面の表示獲得枚数を記録し、差枚・差玉・純増とは別概念。
- AT経由: 記録済みの成功CZに1件ずつ紐付ける。該当がなければ「その他/不明」として記録（直撃を自動で断定しない）。

## 4. 操作要件
R01: 画面上部に通常GとCZ結果を置き、1操作でCZイベントを追加する。
R02: 成功CZの後にAT終了時獲得枚数を入力して記録する。成功CZに自動連携する。
R03: 未確定CZは履歴から「成功」「失敗」に確定できる。
R04: 履歴は発生順で確認でき、各行を削除できる。CZ削除時は連携するATも削除することを明示する。
R05: 最新の情報はlocalStorageに自動保存され、再読み込みしても復元する。
R06: 日付/店舗/台番号は任意で編集できる。
R07: 集計: CZ件数、成功/失敗/未確定件数、記録区間G合計、CZ当選までの記録区間平均、AT件数、平均/総獲得枚数。
R08: コピーボタン1回で日本語AI分析用プロンプトをクリップボードに送る（不可時は選択可能なテキストを表示）。
R09: JSONを書き出し・取り込み可能にし、フォーマット不正時は既存データを維持する。
R10: 新しい実戦を始める際は確認ダイアログを出し、前回データをバックアップするよう表示する。
R11: iPhone Safariでタップしやすい配置・数字キーボード・暗色ネオンの配色を使う。
R12: 正常な操作で計算結果にNaN/Infinityを出さず、空欄・マイナス・小数を記録しない。

## 5. 記録スキーマ (v1)
```json
{
  "schemaVersion": 1,
  "meta": {"date":"2026-10-12","hall":"","machine":""},
  "events": [
    {"id":"cz-001","type":"cz","games":225,"outcome":"hit","at":"2026-10-12T00:00:00.000Z"},
    {"id":"at-002","type":"at","coins":920,"sourceCzId":"cz-001","at":"2026-10-12T00:05:00.000Z"}
  ]
}
```
CZ `outcome`: `pending` / `hit` / `miss`。AT `sourceCzId` は紐付ける成功CZのIDまたは `null`（その他/不明）。

## 6. AI出力原則
- 元データと集計値を両方出し、CZ→ATの対応関係、未確定結果、未記録区間の可能性を明示。
- 観測Gから導く値は「記録区間の参考値」と呼び、完全な実戦総Gベースの確率と混同しない。
- **ATの獲得枚数それ自体を設定差・高設定の根拠とみなさない**。評価は別途機種解析値と照合する。
- 投資の増額・継続を促す文言は生成しない。

## 7. 受け入れ基準
| ID | 操作・条件 | 期待結果 |
| --- | --- | --- |
| A01 | CZ 150G 成功、CZ 200G 失敗を追加 | CZ=2、成功=1、記録G=350、区間平均=175 |
| A02 | 成功CZ後にAT 1,200枚を追加 | 対応するCZ IDとATが結びつき、獲得枚数合計=1,200 |
| A03 | 未確定CZを成功へ変更 | 成功が1増え、未確定が1減る |
| A04 | AT紐付け済みのCZを削除 | 紐付いたATも同時削除し、孤立したATが残らない |
| A05 | 入力が空/負数/小数 | 登録拒否し既存データを維持 |
| A06 | 保存後にリロード | 全イベントとメタが復元される |
| A07 | AI文を生成 | 全イベントの時系列・集計・定義・設定推定上の留意点が含まれる |
| A08 | JSONを読み戻す | 記録内容が復元。破損データは拒否して既存記録はそのまま |
| A09 | 未連携の成功CZがない状態でATを記録 | その他/不明として記録し「直撃」と断定しない |
| A10 | 新しい実戦を開始 | 確認を求め、承認後はイベントが空になる |
